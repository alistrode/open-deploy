# OpenDeploy / PXVIRT 流程设计

> 当前现场已采用分段 RAM 引导；旧单文件 newc 方案不能直接覆盖现场。具体序列号、模式和证据仅见 HANDOFF.md。当前任务仅准备并安装实体 PXVIRT，C/D 可清、E 资料保留；不安装 Windows/Tiny10、不增加界面或连接组件。下文 Tiny10/模拟路线属于历史设计，不是本次要执行的任务。实际进度及用户“先别装机”的限制以 `HANDOFF.md` 为准。



## 共用要求

PXVIRT 启动盘只包含 PXVIRT 8.4-2 安装内容、安装配置及必要部署工具，不包含来宾安装镜像。PXVIRT 就绪后，再由用户指定来宾安装镜像及其可访问位置。VirtIO 驱动介质也在安装来宾时准备。

两个流程均使用仓库分支执行部署，不对 ISO 做哈希检查，不触发 Windows 系统更新，不安排独立核实、检查、测试或额外验收轮次；从头到尾执行一次，发生具体错误时从中断处继续。

## 流程一：真机部署

```text
Windows 准备电脑
    |
    +-- 使用仓库分支制作实体 PXVIRT 启动 U 盘
    |       |
    |       +-- PXVIRT 8.4-2 安装内容
    |       +-- PXVIRT 安装配置及必要部署工具
    |
    +-- 目标实体电脑从该 U 盘启动
    |       |
    |       +-- 将 PXVIRT 安装到指定的实体硬盘
    |
    +-- 目标实体电脑从硬盘启动 PXVIRT
    |
    +-- 连接 PXVIRT 并完成配置
    |       |
    |       +-- 网络和存储
    |       +-- SSH、管理网页和远程连接
    |       +-- 处理实际出现的问题
    |
    +-- 由用户指定来宾安装镜像及其位置
    |       |
    |       +-- 使用 PXVIRT 已有存储中的 ISO
    |       +-- 或上传本地 ISO
    |       +-- 或接入 PXVIRT 能访问的共享存储
    |
    +-- 准备 VirtIO 驱动安装介质
    |
    +-- 在 PXVIRT 内创建 Tiny10 虚拟机
    |       |
    |       +-- 分配 CPU、内存、虚拟硬盘和网卡
    |       +-- 挂载用户指定的安装镜像和 VirtIO 驱动介质
    |
    +-- 安装 Tiny10 到虚拟硬盘并启动
    |       |
    |       +-- 安装器需要时加载 VirtIO 存储驱动
    |
    +-- 在 Tiny10 内配齐所需驱动
    |       |
    |       +-- 存储、网卡、显示、串口等虚拟硬件驱动
    |       +-- QEMU Guest Agent
    |       +-- 使用硬件直通时安装对应硬件驱动
    |
    +-- 配好 Tiny10 网络、远程桌面、所需软件和代理
    |
    +-- 正常使用 Tiny10
```

系统层次：实体电脑 → PXVIRT → Tiny10 虚拟机。

## 流程二：虚拟机内模拟部署

只使用指定的新外层虚拟机模拟目标实体电脑，不写宿主机物理盘。外层 Windows 初装可使用虚拟机托管的 Windows ISO；做盘前提满足后，只连接进入外层来宾完成后续操作，不再调整外层虚拟机的磁盘或启动配置。PXVIRT 必须通过仓库分支制作的介质安装，不能改成宿主机挂载 PXVIRT ISO 代装。不允许任何核实和检查，不允许任何测试，只需要一次模拟从头到尾完成流程就行，不需要任何检查

外层采用 NAT 时，PXVIRT 管理网络与内层 Tiny10 使用不同子网。在 PXVIRT 内配置 Tiny10 的私有网桥、地址分配和出站转发，避免两个系统取得同一管理地址。该配置范围限于 PXVIRT 内部。

```text
宿主机提供一台新的外层虚拟机
    |
    +-- 初装外层 Windows 准备环境
    |       |
    |       +-- 此步骤可使用虚拟机托管的 Windows ISO
    |       +-- 预先具备做盘和后续安装需要的虚拟设备与启动条件
    |
    +-- 做盘前提满足后，只连接进入外层 Windows 来宾
    |
    +-- 在来宾内使用仓库分支制作 PXVIRT 启动介质
    |       |
    |       +-- 将专用虚拟介质作为启动 U 盘的模拟对象
    |       +-- 写入 PXVIRT 安装内容、配置及必要部署工具
    |       +-- 不写宿主机物理盘
    |
    +-- 外层虚拟机从上述介质进入 PXVIRT 安装
    |       |
    |       +-- 通过来宾内操作及控制台连接推进
    |       +-- 将 PXVIRT 安装到专用目标虚拟硬盘
    |
    +-- 外层虚拟机从目标虚拟硬盘启动 PXVIRT
    |       |
    |       +-- PXVIRT 替代外层 Windows，成为外层虚拟机内的系统
    |
    +-- 连接 PXVIRT 并完成配置
    |       |
    |       +-- 网络和存储
    |       +-- SSH、管理网页和远程连接
    |       +-- 处理实际出现的问题
    |
    +-- 由用户指定 PXVIRT 可访问的来宾安装镜像
    |       |
    |       +-- 已有 ISO / 上传本地 ISO / 共享存储
    |
    +-- 准备 VirtIO 驱动安装介质
    |
    +-- 在 PXVIRT 内创建 Tiny10 虚拟机
    |       |
    |       +-- 挂载用户指定的安装镜像与 VirtIO 驱动介质
    |       +-- 按需提供离线中文语言组件
    |
    +-- 自动安装 Tiny10、驱动和 Guest Agent
    |
    +-- 配置网络、远程桌面、所需软件和代理
    |
    +-- 正常使用 Tiny10
```

系统层次：宿主机 → 外层虚拟机中的 PXVIRT → 内层 Tiny10 虚拟机。外层 Windows 只用于前期做盘，安装 PXVIRT 后不再作为运行层保留。

用户已明确继续 Tiny10 来宾阶段。该阶段依赖外层环境实际提供嵌套 VT-x/AMD-V，使 PXVIRT 内的 KVM 可用；保留硬件虚拟化要求。

## 自动范围与恢复材料

自动范围止于安装 PXVIRT 并建立稳定部署连接；进入 PXVIRT 后安装 Tiny10 不要求全自动。首次模拟装机实际有效、而现有程序尚未包含的处理，按 `.agents/skills/opendeploy-recovery/SKILL.md` 选择 `source/pve/recovery/` 下的原脚本。脚本不接入默认流程。VirtualBox 内嵌套 PXVIRT 的专用处理与实体电脑上的 PXVIRT 分开，不把嵌套 EPT、VirtualBox NAT 地址或本次私网配置当作真机默认值。

“一键”允许用户点击和选择、分步启动已有产品入口；不以点击次数判定完成。第一次基准为做好PXVIRT盘、切换启动、装好PXVIRT并建立AI连接，该次有效源码已上传。本次实际系统层次和介质路线符合模拟流程图，后续Tiny10人工恢复归于图中的实际问题处理；没有实体电脑全流程结果，长期持续连通与当前机器状态按实记录。首次安装结果、当前现场未完成事项见 `HANDOFF.md`。


## 2026-10-28 本地硬盘镜像引导模式

保留原完整镜像写盘模式。新增入口 Start-Windows.ps1 -HardDiskIso E:\OpenDeploy-PXVIRT.iso，
调用 source/pve/windows/Start-HardDisk-USB.ps1 与 prepare_harddisk.py。F: 只携带 GRUB、
安装后首启连接所需 payload；中继保持原固定归档压缩状态，首启验证后在系统盘解压；E: 的定制安装镜像经 NTFS 卷序列号和固定路径定位，
由 GRUB initrd 的 newc:pxvirt.iso: 输入完整载入内存，交给原 PXVIRT 内存安装源入口。
源镜像下载到准备电脑直接进行；不经 SSH/MQTT 中继传文件。

此入口必须使用已有正式配置中的精确目标标识，缺失不回退图形选盘。普通序列号沿用原
ID_SERIAL_SHORT/SERIAL；本机使用固定 NVMe EUI，并统一通过 ID_WWN/WWN 绑定。
安装器沿用原自动应答、原首启兼容包、register/bootstrap 及后台连接服务，不增加用户操作。
connection-identity 是唯一原身份源；U 盘 relay-state 必须保留原 start.cjs 所需的
connection-private.json，不能删掉后依赖启动时重新生成。已有自有引导盘可复用布局，
保留私密备份和原身份；不因更新部署文件而重做分区。

引导盘为 BIOS/UEFI GRUB 2.12-9+deb13u2，包含 NTFS 模块；EFI 文件不具有固件信任签名。
开启 Secure Boot 的目标需关闭后使用；本机已关闭。做盘不重启，安装时才显式调用原 Boot-Media 的真机一次性 USB 启动参数；用户当前要求先不安装。
现有 2,013,265,920 字节 U 盘使用容量绑定的 FAT32 布局，原无效序列号不作为唯一依据；
写入还核对 USB 类型、非系统盘、UniqueId、容量和打开的物理句柄长度。
镜像必须完整留在内存直到安装结束，不能把仅 GRUB loopback 当作 Linux 已有安装源。
本轮不实施实体安装，介质制作与实际安装验收分别报告。
